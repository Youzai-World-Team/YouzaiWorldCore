# 聊天消息样式

聊天栏使用固定的八种格式，类型标签在各语言下保持以下中文文字。

| 类型 | 示例，连续收到三次时 |
| --- | --- |
| 玩家普通聊天 | `[聊天]\|Lv.16·{管理员}zxabinbina >> Hello World! [!3]` |
| 玩家私信 `/tell`、`/msg`、`/w` | `[私信]\|Lv.16·{管理员}zxabinbina >> Hello World! [!3]` |
| 游戏命令和系统通知 | `[游戏]\|Server >> Hello World! [!3]` |
| 模组通知 | `[模组]\|YouzaiWorldCore >> Hello World! [!3]` |
| 成就、目标和挑战 | `[成就]\|Lv.16·{管理员}zxabinbina >> 达成进度 [钻石！] [!3]` |
| 加入服务器 | `[加入]\|Lv.16·{管理员}zxabinbina >> 加入了服务器 [!3]` |
| 死亡 | `[死亡]\|Lv.16·{管理员}zxabinbina >> zxabinbina 被骷髅射杀 [!3]` |
| 退出服务器 | `[退出]\|Lv.16·{管理员}zxabinbina >> 退出了服务器 [!3]` |

等级取自 `PlayerLevelStorage` 中的冒险等级；尚无记录时使用初始等级 1。称号使用当前佩戴的文字组件，未佩戴则省略称号，不显示空花括号，等级后的 `·` 仍保留，例如 `[聊天]|Lv.16·zxabinbina >> Hello World!`。玩家名使用账户代号，不附加展示名装饰。私信的发送者、接收者视图都显示实际发送者，非玩家私信来源不显示等级、点号或称号。

`/say` 等命令广播及 `/tellraw` 使用 `CommandSourceStack` 当前执行者名称，所以 `/execute as` 之后仍显示实际实体。无明确执行者的系统通知使用 `Server`。模组提示在标准 Minecraft 消息入口根据实际调用类和 Fabric 目录识别发送模组；已合并到原版类的 Mixin 通过 `MixinMerged` 来源标记识别。使用独立通道的模组可调用 `ChatMessageStyle.mod(显示名称, 正文组件)` 明确标记来源。

正文保留原始文字，不展开玩家输入中的文本标签、百分号占位符或动态变量。`/tellraw` 的 JSON 仍由原版解析；正文、翻译参数及子组件保留原有颜色（包括显式白色）、字体、加粗、斜体、点击和悬停等属性。未指定颜色的文字继承父组件颜色，没有原色时使用下表的默认正文色。两套配色只覆盖前缀字段，不重染正文。

## 玩家头像与名称悬停

玩家名称左侧使用原版行内头像，保留皮肤的面部和外层。已同步的自定义皮肤也会用于头像。打开聊天栏后，鼠标悬停在头像或名称上可查看资料卡，包含玩家名、冒险等级、当前升级经验／下一级所需经验、佩戴称号和游戏模式。例如：

```text
玩家：Alex
冒险等级：Lv.1
升级经验：120 / 200
佩戴称号：未佩戴
游戏模式：生存模式
```

头像和资料覆盖普通聊天和私信发送者、四类事件前缀、玩家执行的 `/say`、`/tellraw` 及原版命令反馈来源，以及私信发送确认中的每位收件人。正文保留成就、武器等原有的悬停说明。

在 `/msg`、`/tp`、`/execute as` 等命令的目标补全中，在线玩家条目左侧也会显示皮肤头像。按 Tab 或点击条目时填入玩家名称。

`ChatPlayerInfo` 在服务端使用已有的等级、称号和游戏模式数据生成 `HoverEvent.ShowText`，不创建等级记录、不请求外部服务。没有等级记录时显示 `Lv.1` 和零经验，没有称号时显示「未佩戴」。所有字段随客户端语言翻译。

资料是消息发送时的快照，历史重绘或玩家退出后仍能查看当时的信息。纯色与渐变名称的每个 Unicode 码点都保留同一资料卡，换行、缩放和重复消息合并后仍可悬停。资料发生变化时，新消息携带新的快照，按完整样式比较开始新的重复组。

## 系统事件

成就、加入、死亡、退出都使用 `[类型]|Lv.n·{称号}玩家代号 >> 正文`。没有称号时省略花括号并保留 `·`，首次加入且没有等级记录时使用 `Lv.1`。

- 成就按原版类型分别显示「达成进度 [名称]」「完成目标 [名称]」「完成挑战 [名称]」。名称继续使用原版 `Advancement.name` 组件，保留颜色及悬停描述；数据包和模组成就也走同一入口。是否广播仍由原版完成判定、`announce_to_chat` 及 `showAdvancementMessages` 游戏规则控制。
- 普通加入的默认正文是「加入了服务器」，首次加入是「首次加入服务器，欢迎！」；改名加入是「加入了服务器（原名：OldName）」。默认退出正文是「退出了服务器」。这些正文按客户端语言翻译，默认模板不会再在正文重复玩家信息。
- 死亡正文保留完整原版描述，包括死者、击杀者、武器及其交互信息，因此死者名字仍会在完整死因中出现。示例：`[死亡]|Lv.16·zxabinbina >> zxabinbina 被 Alex 使用 [钻石剑] 杀死`。
- `chat_format_module` 中已有的内置加入、退出模板识别为默认事件正文；自定义模板继续解析并放在事件前缀之后，支持原有变量和文本标签，`${default_message}` 可插入默认事件正文。配置文件不做迁移。
- `chat_format_module.enabled` 控制四类事件样式；关闭后各事件入口保留原版文本，再由通用系统消息入口显示为游戏通知。默认开启。

## 配色与切换

默认启用**方案二：渐变点缀**。使用客户端命令切换，名称支持 Tab 补全，无需 OP 权限：

| 命令 | 行为 |
| --- | --- |
| `/yzwc chat_style gradient` | 方案二：渐变点缀 |
| `/yzwc chat_style plain` | 方案一：官网色板纯色映射 |
| `/yzwc chat_style` | 查询当前配色及可用名称 |

切换后立即重绘现有聊天记录，连续重复组与累计次数保留。设置保存在本机 `yzwc/client/global_settings.json` 的 `chat_style_module` 分节，键为 `style`，默认值 `gradient`；退出游戏后仍保留。非法命令名称不会修改设置；手动写入非法配置时遵循统一配置层的隔离、重建及报错流程。

单人游戏同样使用客户端配色命令。原版补全树已有服务端 `/yzwc` 根时，Fabric 3.1.2 的客户端命令合并会把子节点挂到未接入该树的副本上。`ClientCommandSuggestionsMixin` 在合并结束后将完整的配色子树接到补全树中，使 `chat_style`、`plain` 和 `gradient` 可见；实际执行继续使用客户端命令树。

### 两套方案的公共颜色

| 元素 | 颜色 |
| --- | --- |
| `Lv.xx` | `#F36B7B` |
| `{称号}` | `#F47B8A` |
| 正文（未指定原色时） | `#f3efef` |
| `[!N]` | `#2DD4BF`（青色） |
| `|`、`·`、` >> ` | `dark_gray`（`#555555`） |

游戏执行者使用橙色，模组名使用蓝色；渐变方案中名称分别过渡到金橙色和紫色。所有消息类型的重复计数统一使用青色，两套方案均生效。普通聊天和私信玩家名继续按各自方案着色。

颜色与渐变对应 [MiniMessage 语法](https://docs.papermc.io/adventure/minimessage/format) 的指定效果，由 Minecraft 文本组件实现。每个渐变标签或名称单独从起点颜色过渡至终点颜色，按 Unicode 码点插值，避免将表情的代理对拆开。正文中的 `<gradient:...>` 等文字保持原文，不作为格式解析。计数仅次数大于 1 时追加，前面恰好一个空格，例如 ` [!3]`，单条消息没有计数或额外尾部空格。

### 自发自收私信

原版 `/tell` 对每个目标分别发送一条发送回执和一条收到私信。目标是自己时，同一客户端会收到两条；统一双方显示格式后，两条会被合并器累计为 `[!2]`，连续使用时因此每次加 2。

`MsgCommandMixin` 在收件人包含发送者时跳过额外的原版正文回显，保留原版收件路径，所以自发自收的正文每次只投递、计数一次。未包含自己的目标仍按原版分别发送正文回显和收件，消息签名及过滤规则保留。

`/tell`、`/msg`、`/w` 完成投递后额外向发送者追加一条明确的聊天栏确认，例如 `[私信]|Lv.16·{管理员}zxabinbina >> 已发送给 Alex`。给自己发送时也有确认，多目标合为一条并列出收件人，不重复私信正文。完全过滤的目标不列入成功确认；所有目标都被完全过滤时只保留原版失败反馈，静默命令不新增确认。

发送确认的正文使用结构化语言键 `chat.youzaiworldcore.private.sent_to`，客户端单独显示它，不增加或打断真实私信的重复计数；原始历史仍保留这条回执。界面重排和历史裁剪后正文累计次数保留，玩家输入相同的“已发送给”文字仍按普通正文参与计数。

## 发送与显示

- `youzaiworldcore:chat_line` 的前缀和正文分别使用 `sender`、`content` 参数，正文继续通过原版签名和过滤流程；部分过滤文本不会因完整正文放进前缀而重新暴露。
- 服务端生成的等级、点号、玩家名及来源组件已有基础配色，玩家名默认携带对应渐变；前缀及聊天类型默认正文色为 `#f3efef`。正文原始组件继续独立保留，客户端按选择的方案为显示副本的前缀着色，正文及附加文本保留原色。
- 普通聊天、私信和命令排版固定。`chat_format_module.enabled` 控制成就、加入、离开和死亡事件样式；加入、离开和死亡的自定义正文模板继续读取，旧 `chat_format` 和两种私信模板不再读取，也不迁移旧配置。
- `SystemChatPacketMixin` 只处理聊天栏系统消息，跳过动作栏。`CommandSourceStackChatMixin` 保留成功、失败及管理员广播的执行者；`TellRawCommandMixin` 包装解析后的原文。
- `PlayerAdvancementsChatMixin` 只替换成就广播点的 `AdvancementType.createAnnouncement` 调用，不修改奖励或显示条件。事件前缀可被结构化识别，通用系统消息入口不会再添加 `[游戏]` 或 `[模组]` 前缀。
- 客户端在显示队列中合并连续相同消息，比较来源、完整组件与消息标签。首次不显示计数，第二次起显示 `[!n]`；来源、等级、称号、正文、样式或标签改变时开始新组。
- `ChatMessageRenderer` 只为显示副本着色，合并器始终使用原始消息对象分组及保存历史序号，实际彩色显示对象用于替换旧换行记录。切换配色通过 `rescaleChat()` 重放原始历史，不把计数后缀或显示颜色写回原文。
- `allMessages` 保留每条原始消息和签名。显示组使用最新一条消息的时间、标签及签名；只替换该组的换行显示记录。重排、可见过滤及删除标记会按原始历史重新分组，清空后重新计数。
- 计数缓存使用消息对象身份，跟随原版最多 100 条历史裁剪。被历史上限截掉的同组计数在窗口重排时仍保留；删除标记作为新的游戏消息参与分组。

## 验证

运行 `python3 tools/verify_chat_messages.py`；本地没有 `javac` 命令时可用 `--java-home <JDK25目录>`。脚本执行实际格式化、称号组件、发送入口、配色、合并、配置和命令 Java 代码，以替身隔离 Minecraft 与绘制，使用本地缓存的 Brigadier、Gson 以及实际统一配置存放层在临时目录验证解析和保存，不运行 Gradle 或游戏。

运行 `python3 tools/verify_chat_runtime.py` 检查原版链路，同样支持 `--java-home`。此脚本使用 Minecraft 26.3 的真实组件、网络编解码器、`GuiMessage.splitLines`、`StringSplitter`、`GuiTextRenderState`、`Font` 和 `ActiveTextCollector.findElementUnderCursor`，以及真实 Fabric 客户端命令合并逻辑；测试字形提供固定字宽和活动区域，并记录真实字体传给字形的 ARGB，覆盖默认白色绘制参数、聊天透明度和 `/say` 的前缀结构。悬停检查模拟鼠标移动，验证换行及缩放后玩家名能命中同一资料卡，其他字段不会误显示玩家资料。静态注册表在离线进程初始化，原版 jar 的测试副本位于临时目录，类字节保留原样。该检查不创建 GPU 上下文，不能代替游戏截图的像素检查。

检查包含八种示例与计数、未佩戴及初始等级、首次及改名加入、退出和死亡入口、三类成就、事件开关和自定义正文模板、正文特殊字符、模组和 Mixin 来源、动作栏跳过、实际执行者、部分及完全过滤、签名、连续性、不同来源及样式、历史裁剪、窗口重排、删除标记、同 tick 消息和计数溢出。配色检查覆盖两套所有元素、渐变端点与 Unicode 中间色、翻译参数和正文交互保留、命令查询与补全、配置落盘及重载、非法命令不修改状态、坏配置恢复、即时换色及换色后计数。另核验十种语言及 Mixin 注册。

自发自收回归从 Minecraft 26.3 原版 jar 提取 `MsgCommand.sendMessage` 的实际投递循环，将格式化及回执入口接入现有 Mixin。验证修复前每次两条、修复后每次一条，并覆盖未签名消息、其他玩家、包含自身的多目标、控制台与原版过滤，以及独立发送确认、交错回执的历史裁剪与重排、完全过滤和静默反馈。当前基础回归通过 493 项断言，原版链路回归通过 3635 项断言；后者覆盖原版编解码后的两套色板、宽窄聊天窗口分行、原版聊天颜色开关、玩家及来源名称渐变、计数色、真实字体生成的绘制 RGB 与透明度，以及同名根的补全修复。字体检查明确比较原版 `#ffffff`、游戏名称 `#FF8A00`、模组名称 `#5B8CFF` 和计数 `#2DD4BF`，四者在字形输入端保持不同 RGB。未执行完整 Gradle 构建或实服验证。

配套更新客户端和服务端后，在测试服检查：

1. 两名不同等级、不同称号的玩家普通聊天与 `/tell`，核对双方前缀；卸下称号后保留 `·`，不出现 `{}`。
2. 玩家、控制台和 `/execute as` 实体分别执行 `/say`；用 `/tellraw` 发送带颜色或点击事件的 JSON 正文，核对来源与交互。
3. 触发 Core 登录、命令或地图提示，以及其他 Fabric 模组提示，核对模组名称；动作栏不添加聊天前缀。
4. 连续发送相同消息、插入不同消息、改变称号或等级后再发送；检查换行、滚轮、窗口缩放、聊天过滤、清空和删除标记，确认计数及原版历史行为。
5. 连续三次 `/tell 自己 相同正文`，确认正文依次不显示计数、显示 `[!2]`、显示 `[!3]`，每次额外收到“已发送给”确认；多目标包含自己时，自身正文仍只收到一次，确认合为一条并列出目标。
6. 单人游戏及多人服务器中，在 `/yzwc ` 后检查原版补全列表包含 `chat_style`，并检查两个方案名的补全。使用 `/yzwc chat_style plain` 与 `/yzwc chat_style gradient`，核对八类消息颜色及历史记录即时变化；检查重复次数不变、无参数查询，并重启客户端确认配色保留。
7. 使用新玩家首次加入、老玩家重连和改名加入，核对欢迎语与旧名；退出后检查退出样式。触发普通死亡和带武器的玩家击杀，检查完整死因及武器悬停。
8. 完成普通进度、目标和挑战，检查金色标签、成就名称原色与悬停说明；关闭 `showAdvancementMessages` 后确认不广播。使用自定义事件正文并关闭事件样式，核对模板与开关行为。

9. 打开聊天栏，悬停普通聊天、私信、事件和玩家游戏消息的来源名，再悬停私信确认中的不同收件人，核对各自的等级、经验、称号及模式。切换配色、缩放和换行后仍可查看；更新玩家资料并发送新消息，确认旧消息保留旧快照。

## 重写前的格式化方式

以提交 `d58d2a5` 的实现为准：服务端 `ChatFormatSettings` 从 `chat_format_module` 读取普通聊天、私信及事件模板；`ChatFormatHelper` 使用 Placeholder API 的 `NodeParser` 解析颜色标签、`%papi%` 和 `${变量}`，生成完整的 `Component`。

普通聊天先通过 `ChatDecorator` 处理正文，再把完整模板结果写进 `PlayerChatMessage` 的 `override` 扩展参数。`OutgoingChatMessage.create` 被 Mixin 替换为 `StyledChatMessage`，用 `youzaiworldcore:generic_hack` 聊天类型的 `%s` 模板直接显示完整结果。

启用旧格式时，私信还会拦截原版发送回执，在收件分支分别套用“发出”和“收到”两个模板再投递。给自己发时会显示两种不同视图，旧版没有重复消息合并计数。本次重写将前缀和正文分开，并新增客户端显示合并；此次修复补上了双方统一格式后的自发自收回执处理。
