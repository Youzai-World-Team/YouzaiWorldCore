# AFK 验证说明

AFK 状态在服务端主线程维护。`AfkActivityState` 负责通道选择、活动序号和计时，
`AfkManager` 负责会话与广播，`AfkTickHandler` 每 20 tick 驱动检测。

## 手动切换的输入边界

1. 客户端即将发送聊天/命令包时，先记录一次活动，并立即发送包含该输入序号的心跳。
2. 服务端按包顺序接收心跳、聊天/命令活动和切换命令；进入 AFK 时快照各通道序号。
3. 之后相同输入序号的心跳只保活。网络延迟变化、回车松开、鼠标重新捕获不产生新操作。
4. 真实的新按键/点击/世界内鼠标移动递增序号，可以在下一次检测恢复状态，没有固定宽限期。

聊天数据包入口可能处于网络线程，所以普通聊天、普通命令和带签名命令的活动记录都先排入
服务端主线程，早于原版随后排队的命令执行。不要改回网络线程直接写状态。

`BOTH` 在客户端心跳有效时，进入与退出都只采用客户端输入以及明确的聊天/命令活动。
服务端采样的移动不会覆盖客户端判定。`SERVER` 对进入与退出都只采用位置/视角和聊天/命令。
`CLIENT` 无有效心跳时不自动进入；没有客户端通道的手动 AFK 仍允许移动恢复。

## 独立回归

```bash
python3 tools/verify_afk.py --java-home /path/to/jdk-25
```

脚本在临时目录编译并运行实际 `AfkActivityState`、`AfkConfig`、`AfkInputTracker`、
键盘及鼠标 Mixin 方法。Minecraft、Fabric、Mixin 注解和配置存储使用最小替身，
不构建整个模组、不下载依赖，也不修改运行配置。它验证状态机和输入过滤行为，
不替代真实 Mixin 注入、网络往返和服务端伤害测试。

## 联机验证

按项目约定由开发者构建，并在专用开发服务端验证。客户端与服务端同时更新，使用
`afk_heartbeat_v2` 和 `afk_state_v2`；旧协议不与新字段混用。

建议测试服临时使用以下设置，测试完成恢复原值：

```text
/yzwc afk settings detect_mode BOTH
/yzwc afk settings threshold 30
/yzwc afk settings auto_kick 60
```

| 场景 | 预期 |
| --- | --- |
| 输入 `/yzwc afk` 后释放回车并保持不动，重复多次 | 一直保持 AFK，不出现紧接着的返回广播 |
| 高延迟下手动进入，后续旧心跳继续到达 | 旧心跳不唤醒；随后真正按键或点击可恢复 |
| 只打开/关闭聊天框或物品栏，不做其他操作 | 不恢复；修改物品栏/聊天快捷键后规则仍成立 |
| 持续按住 W，且不操作鼠标 | 30 秒后进入 AFK，键盘重复不刷新计时 |
| 玩家不输入，乘矿车或被流水推动 | BOTH 有有效心跳时能进入并保持 AFK；再挂机 60 秒后踢出 |
| SERVER 模式下站着持续聊天或执行命令 | 不自动 AFK；从最后一次消息或命令重新计时 |
| AFK 后发送普通命令、聊天或带签名的私聊命令 | 恢复，随后静止需完整 30 秒才重新 AFK |
| AFK 后再次执行 `/yzwc afk` | 退出，不在下一次检测立即重新进入 |
| 没有支持通道的客户端，BOTH 模式 | 回退服务端检测；CLIENT 不自动进入；手动 AFK 可走动退出 |
| 启用无敌后在 AFK 中受到普通、饥饿、虚空及 `/kill` 伤害 | 伤害被阻止；退出或关闭配置后恢复正常伤害 |
| 进入前已有抗性效果，期间喝奶或获得新抗性 | AFK 不添加/恢复/移除任何抗性效果 |
| 修改 `prefix`，分别切换 Tab 与名字牌开关 | 现有 AFK 玩家立即更新；新加入的观察者收到当前显示状态 |
| 手改 `afk_module` 后执行 `/yzwc reload` | 配置和显示同步；关闭功能清状态；重新启用或切换模式重新建立活动基线 |
| 退出服务器后重新连接 | 旧 AFK 状态和客户端输入序号清理，新的会话重新计时 |

无敌默认关闭。开启后 `/kill` 也受伤害拦截；测试时可先关闭 `invulnerable` 再进行清理。
客户端输入属于自报信号，序号用于去重和划定操作边界，不是反作弊凭据。
