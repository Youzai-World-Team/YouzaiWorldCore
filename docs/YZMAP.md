# 悠哉地图（YZMAP）

YZMAP 包含游戏内小地图/全屏地图、Minecraft 服务端共享和 YouzaiWorldApi 后台地图。功能根据 Conflux Map 的公开说明独立实现，不引入其代码、资源或依赖。

## 操作与保留功能

| 默认键 | 功能 |
| --- | --- |
| `M` / `H` | 全屏地图 / 小地图开关 |
| `N` | 在当前位置新建路径点 |
| `U` / `J` | 路径点列表 / 显示开关 |
| `Y` | 切换地形模式 |
| `[` / `]` | 缩小 / 放大小地图 |
| `,` / `F9` | 地图设置 / 刷新与重新订阅地形 |

按键均可在控制设置中重绑。本机命令为 `/yzwc map [settings|waypoints|add|refresh]`。

全屏地图支持拖动、以鼠标为中心缩放、维度选择、坐标定位、玩家跟踪、路径点管理，以及画笔、直线、矩形、椭圆、文字绘图。保留绘图的移动、改色、删除和最近 32 步撤销/重做；撤销历史不跨重启。地图不再记录或显示玩家行走轨迹。

全屏地图的「玩家」入口打开「位置共享」面板。顶部选择「仅共享名单」或「所有人（黑名单除外）」；下方用「可见玩家／共享名单／收到申请／黑名单」四个页签显示人数。可按名称或 UUID 搜索，卡片显示头像、在线状态，可见位置支持定位和跟踪；添加共享玩家、申请查看位置及拉黑使用独立的在线玩家选择列表。窄窗口显示紧凑卡片，列表支持分页与滚轮翻页，刷新保留搜索和焦点。共享操作以服务端确认结果为准，等待时禁用重复操作，拒绝或超时会显示提示。

「共享名单」表示谁可查看你的位置，「可见玩家」表示谁向你共享位置，两者方向不同。开放模式下移出共享名单不会停止共享，拉黑才会阻止对方查看你的位置和发送申请；同意申请会将对方加入共享名单。管理列表读取服务端实际授权的位置，不受地图玩家图标显示开关影响，过期位置不可定位；原位置共享总开关仍有效。

全屏地图的「雷达」以图标网格列出注册表中全部已启用的生物种类（包括模组生物），可按本地化名称或注册 ID 搜索。即使附近没有鸡，也可以先选中「鸡」；选择后持续查找模拟范围内全部匹配生物，在全屏地图和小地图同时显示高亮纹理图标，不再从最近实体列表中挑选一个 UUID。范围外进入的生物自动加入，死亡、隐身或离开的生物自动撤下。关闭面板不停止查找，「取消定位」或再次点击所选种类可停止，断线清除选择。「查看地图」居中展示整片模拟范围；小地图保留自身缩放，视口外的匹配目标显示边缘图标和方向箭头。

查询按区块计算水平范围，高度覆盖当前维度，半径取玩家模拟距离设置与服务端模拟距离的较小值。新版配套服务端每秒响应按种类查询，从现有实体空间索引读取，不加载或生成区块；因此不受原版较短的客户端实体跟踪范围限制。新增 `map_mob_query` / `map_mob_snapshot` 协议，两端更新后生效；旧服务端或未连接地图服务时只使用客户端已知实体，并在面板标明「本机查询」。服务端仍校验认证、地图总开关、当前玩家位置、维度、存活和实体可见性，每位玩家至少间隔 10 tick 接受一次查询。快照按 512 个位置分包，收齐后替换；匹配标记不受普通雷达 256 个绘制项限制。解码总边界为 256 包，超大查询拒绝整份快照，不把截断列表当成完整结果；快照 3 秒后过期，在下一次标记刷新时撤下。切换种类、维度或模拟距离后，旧请求不能覆盖新选择。

所有普通生物雷达标记也使用纹理小图标。立方体模型从头部、鼻口、角耳等部件的正面 UV 提取，共用实际材质并缓存布局，资源包重载后重建；没有头部的模型使用身体纹理，非立方体模型使用原版 GUI 离屏渲染。图标目录使用未加入世界的预览实体，不依赖附近实例；预览对象分配独立的非零负数实体 ID，满足 26.2 渲染器提取装备等状态时的要求，避免未分配 ID 导致整组图标空白。显示设置仍位于「地图设置」；主动选择的生物不受类别显示开关限制，但仍尊重标记图标总开关，关闭总开关时图标与文字一起隐藏。

关闭「显示标记事物图标」时，路径点、锚点、玩家和生物的标记文字也会隐藏，隐藏的标记不再响应地图点击。重新开启图标后，文字按自身显示开关恢复。

路径点保留私人/公共点、分类、私人描述、死亡点、导航、主世界/下界投影和本人已激活锚点。复制坐标生成 `[YZMAP x y z dimension] 名称`；聊天分享打开草稿，由玩家发送。所有地图数据导入/导出入口、命令和实现均已移除，包括本模组 JSON/文本、Xaero/VoxelMap 路径点导入、复制列表及选区 PNG 导出。

自动洞穴判断按玩家头顶上方的有效遮挡数量决定，不再使用原先 6 格高度差：只读取玩家所在的已加载区块，在所在列从最高方块检查到玩家碰撞箱顶部所在格，累计不超过 4 格有效遮挡时视为地表，达到 5 格才切换地下分层。忽略空气、树叶、玻璃（包括染色玻璃、遮光玻璃、玻璃板及常规玻璃标签）、水和无碰撞水草／睡莲，间隔不重置累计值。因此露天树冠下、玻璃屋顶下、地表河水中和薄顶板下保持地表；这些覆盖物之上另有岩石或建筑时，继续累计其有效遮挡。含水的实体台阶／楼梯计入遮挡。所有维度（包括下界）及地下探索层记录共用该判定，地表位置不新增地下到访记录；不删除此前保存的探索记录。

固定高度行为沿用原实现：小地图按设置采样；全屏地图未选择本人已探索地下层时，固定高度设置回落为地表显示。右侧地下层仍只显示玩家当前区块的实际到访记录，浏览服务端切片不会解锁探索历史。

小地图支持圆形、方形、圆角方形，跟随 YZUI 主题并接入 YZHUD 拖动、缩放和透明度。`F1`、死亡、登录大厅和其他界面中的隐藏规则保持不变。

## SQLite 存储

| 内容 | 路径与结构 |
| --- | --- |
| 客户端显示设置、小地图布局 | `yzwc/client/map_module/map.db`，`settings` 表的 `display` / `hud` 作用域 |
| 私人路径点、描述、分类、绘图、视角 | 同库 `records`，按世界身份和记录类型隔离 |
| 客户端到访层、地形 | 同库 `explored` / `client_tiles`，按世界身份隔离 |
| 服务端共享设置、玩家共享规则 | `yzwc/server/data/map_module/map.db`，`settings` 的 `server` / `player:<UUID>` 作用域 |
| 世界 UUID、公共点、地形、区块处理标记、上传进度 | `<world>/data/yzwc/data/map_module/map.db` |
| API 地图 | API 的 `server/data/database.db`（可由 `YZWC_DATA_DIR` 改变目录），`game_map_v2_worlds` / `game_map_v2_dimensions` / `game_map_v2_tiles` / `game_map_v2_layers` |

Core 使用内置打包的 SQLite JDBC；API 使用 `node:sqlite`。Core 地图库启用 WAL，成批写入使用事务。所有 Core 路径由 `ModPaths` 提供。地形/私人记录是内部二进制 BLOB，不是用户可导入导出的文件格式。YZHUD 的全局透明度仍属于通用 HUD 设置，小地图自身布局独立存入地图 SQLite。

本次直接建立新结构：不读取、不迁移、不转换旧地图 JSON、gzip 瓦片或 API 旧地图表，也不删除旧文件。新世界地图库会生成新的稳定世界 UUID；两端需配套更新。地图设置与数据不再由全局 JSON 的 `map_module` 或个人 JSON 读写。

客户端地形会持久保存，断线、重启、刷新和切换世界不会删除数据库中的旧瓦片；不设客户端瓦片容量淘汰规则。只在切换世界时替换内存视图，按批恢复对应地形。客户端本地地图在没有地图服务的服务器上也可使用，私人记录按原有本地身份规则隔离。每个世界仍有 512 私人点、128 绘图和 65536 到访层的功能上限，每条绘图至多 512 个顶点。

## 服务端地形来源与上传

地形链路：Minecraft 区块存储 → 后台采样 → 世界 SQLite → HMAC 增量上传 → API SQLite。

- 新库扫描已有维度 `region/r.*.*.mca` 文件的区块位置和时间戳。从 Minecraft 自己的区块 IO 队列读取磁盘或正在保存的 NBT 快照，解析完整区块的方块、群系和光照，不构造活动区块，也不加载实体。
- 区块保存成功排队后，Mixin 将坐标加入修改队列，同一坐标的多次修改合并；定期扫描补充已有区块。已经卸载、但保存在文件中的历史区域也可生成地图，不需要玩家重新前往。
- 后台生成地表、顶层及每 8 格的洞穴/固定高度切片；其他高度可由地图视口按需请求。已保存的自定义高度切片会随区块修改更新。顶层可查看下界顶板及其建筑，地表显示顶板下方；登录大厅不采集。
- 采样不向 Minecraft 申请加载票。未知区域的浏览先检查文件是否已有区块，避免创建空区域文件。没有保存成完整区块的地形暂不进入服务端地图。
- 一个区块的地形与处理标记在同一事务中提交，内容不变不增加修订号。地形修订号单调递增，上传只读取已提交的指定修订区间。客户端接收和本机采样的数据不会进入这条链路。
- 专用服务端即使没有安装模组的玩家连接，也会采集已保存区块。结构标记仍读取实际加载区块中的结构起点，不预测种子或未生成结构。

上传复用 `api_module.base_url/server_key` 和 `ApiHttp` 的 HMAC 签名。`enabled`、`api_upload` 与 API 网桥均开启时，首次/逾期同步在开服约 60 秒后尝试，之后默认每 2880 分钟（48 小时）同步一次，失败十分钟后重试。时钟独立于游戏 Tick，空服暂停仍可同步已保存数据。`/yzwc map upload` 可由管理员立即安排同步。

协议版本为 `2`，来源固定为 `minecraft_chunk_storage`，采用 `begin` / `tiles` / `complete`。会话携带本轮修订上界，每个瓦片携带自身修订号；API 返回已确认修订号，以较小游标补齐缺失增量。首次、API 地址改变或后台新库时全量上传。每批最多 128 个瓦片，事务、批次序号与内容摘要保障重试不重复计数；只有完整确认才推进本地与 API 的成功游标，中断保留已写入的瓦片。

网页地图是定期更新的采样快照。上传仅含地形颜色、高度和光照，不包含私人路径点、绘图或实时玩家位置。每个 16×16 瓦片为 1792 字节（RGBA 1024、高度 512、光照 256），Base64 传输。API 最多保存 64 个存档、每存档 200 万图层瓦片；超限拒绝整批，保留已保存数据。

## 配置和权限

服务端地图参数存于服务端地图库 `settings` 表，`scope='server'`，值为文本。使用 SQLite 工具修改后执行 `/yzwc reload`；客户端显示设置仍可通过游戏内设置页调整。

| 键 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `true` | 地图共享与采集总开关 |
| `share_terrain` / `share_players` / `share_waypoints` | `true` | 地形 / 玩家位置 / 公共点共享 |
| `share_structures` | `true` | 已发现结构标记 |
| `api_upload` / `capture_underground` | `true` | 自动上传 / 自动生成地下切片 |
| `scan_interval_seconds` | `60` | 完成一轮后开始下一次文件扫描的最短间隔 |
| `chunks_per_pass` | `64` | 后台每轮最多处理区块数，轮次之间间隔 1 秒 |
| `upload_interval_minutes` | `2880` | 完整同步成功后的上传间隔 |
| `share_load_state` / `allow_teleport` | `false` | 区块票据加载信息 / 地图坐标传送 |
| `allow_publish` | `true` | 普通玩家按权限发布公共点 |
| `max_shared_waypoints` / `max_waypoints_per_player` | `512` / `32` | 公共点总量 / 每位普通玩家配额 |
| `bytes_per_second_per_player` | `131072` | 游戏内地形下发限速 |
| `cache_tiles` | `8192` | 仅服务端内存读取缓存；不删除 SQLite 地形 |

客户端采样仍采用每 Tick 列数和时间预算，画布在后台合成后上传纹理。服务端文件采集、数据库地形读取和 HTTP 上传在后台执行；每个保存区块事务独立提交，上传按 128 瓦片分页读取。

玩家位置共享保留总开关、共享名单和黑名单，以及仅名单／开放共享两种范围。未认证、死亡、旁观、隐形或主动隐藏位置的玩家不会出现在共享雷达；实时数据过期会撤下。位置请求仅当前开服有效。公共点发布、编辑、删除、锁定与传送继续由服务端校验认证、所有权和权限。

| 命令 / 权限 | 用途 |
| --- | --- |
| `/yzwc map shared list|add|delete|lock|unlock` | 公共点操作 |
| `/yzwc map position show|hide` | 位置共享总开关 |
| `/yzwc map stats` | 本次连接的地形数量和带宽统计 |
| `youzaiworldcore.command.map.shared` | 普通玩家发布/维护本人未锁定公共点 |
| `youzaiworldcore.command.map.manage` | 管理公共点、手动上传；无 LuckPerms 时 OP 4 |
| `youzaiworldcore.command.map.teleport` | 坐标传送；无 LuckPerms 时 OP 4，仍需开关开启 |

API 后台 `/game-maps` 与 `/api/admin/game-maps*` 要求登录及 `game-maps` 查看权限；视口最多 256×256 区块，每页最多 256 个瓦片，前端逐页绘制并取消过期请求。

## 验证与联机验收

静态验证包括 Java 25 语法解析、Minecraft 26.2 接口签名核对、语言键/注册检查和 API `pnpm build`。隔离 SQLite 检查覆盖批次重试/回滚、修订号、重启恢复和超过旧客户端容量的数据保留，不访问运行期数据库。API 协议检查可执行 `node scripts/check-map-protocol.mjs`。

遵守 Core 开发约定，未执行模组 Gradle 编译或启动游戏。开发者联机验收应重点检查：

1. 新建 SQLite，旧 JSON/gzip 不被加载；客户端重连恢复私人记录、地形与布局，复制坐标和聊天草稿可用，轨迹与所有导入导出入口消失。
2. 无玩家客户端提供地形时，从已有区块文件生成地图；修改并保存区块后，地表、标准切片和曾浏览过的自定义高度切片均更新。
3. 浏览从未生成的远方不创建区域文件、不加载游戏区块；负坐标、下界顶板、洞穴与全屏固定高度行为正确。
4. `/yzwc map upload` 后后台显示地图；中断后重试、重启、空服暂停及修改上传周期均正常。两端同时更新到协议 2。
5. 两个玩家验证公共点、共享名单、隐身过滤、锚点导航和权限限制；切换存档无旧地图混用，绘图撤销/重做及 YZHUD 布局正常。
6. 玩家面板验收：在仅名单／开放共享下分别验证添加、移出名单与拉黑的效果；另一玩家发送位置申请后，同意／拒绝应更新对应页签人数。检查名称及 UUID 搜索、离线名单、空列表、分页、最小 GUI 窗口、服务器拒绝与超时提示；关闭地图玩家图标后仍能管理名单和主动定位／跟踪。
7. 生物雷达验收：没有附近实例时仍可选择鸡；在模拟范围内放置多只鸡（包含超出原版实体跟踪距离的区块），确认两张地图同时高亮全部匹配者，普通猪／牛等标记也为纹理图标。验证负区块坐标、范围边界、缩小模拟距离、进入／离开范围、死亡／隐身、快速换种类与换维度、超过 512 个实例的分包更新、旧服务端本机查询提示、圆形小地图边缘提示、资源包重载和 320×240 GUI 分页。

8. 自动图层验收：玩家头顶同一列有 0～4 格有效遮挡时保持地表、不新增地下探索层，加到 5 格时切换地下并记录到访层，移除一格后恢复地表。验证紧贴头顶与高处顶板、被空气隔开的多层顶板，以及站立／潜行／游泳姿态；空气间隔不重置累计数。高树冠、各种玻璃屋顶和深露天河水不计遮挡；其上累计 5 格石质顶板时仍切地下，含水台阶／楼梯计数。下界内与顶板上同样按遮挡数量判定。手动选层与固定高度行为保持。确认日志不再出现图标预览的 `Tried to access entity ID before ID assignment`。
