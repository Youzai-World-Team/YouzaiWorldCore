# 悠哉地图（YZMAP）

本模块依据 Conflux Map 的功能说明独立实现，未复制其 Java/网页代码、纹理或其他资源，也不依赖参考模组。现已包含游戏内地图、Minecraft 服务端共享及 YouzaiWorldApi 后台网页地图；种子预测、结构预测仍不在范围内。

## 游戏内使用

| 默认键 | 功能 |
| --- | --- |
| `M` | 打开/关闭全屏地图 |
| `H` | 显示/隐藏小地图 |
| `N` | 在当前位置新建路径点，避开本模组已有的 `B` 物品高亮键 |
| `U` / `J` | 路径点列表 / 显示开关 |
| `Y` | 轮换自动、地表、洞穴、固定高度、顶层模式 |
| `[` / `]` | 缩小/放大小地图 |
| `,` | 地图设置 |
| `F9` | 刷新客户端地图，并重新订阅服务端已记录的地形 |

快捷键使用 Fabric 的按键注册接口，出现在控制设置的「悠哉地图」分类中。也可使用 `/yzwc map`、`/yzwc map settings`、`/yzwc map waypoints`、`/yzwc map add`、`/yzwc map import` 和 `/yzwc map refresh`。

全屏地图左键拖动平移，滚轮以鼠标位置为中心缩放；右键空白处建点，右键路径点打开操作页。点击雷达标记可跟踪玩家或实体，重新定位自身或停止导航可取消跟踪。地图顶部可切换维度、地形模式与叠加图层。

底部工具按钮依次切换选择/拖动、画笔、直线、矩形、椭圆、文字和导出选区。选择模式可点选、拖动已有绘图；颜色按钮修改选中绘图，删除按钮或 `Delete` 删除，`Ctrl+Z` 撤销，`Ctrl+Y` / `Ctrl+Shift+Z` 重做。文字标签右键可改字。绘图保留最近 32 步撤销历史，历史不跨重启保存。

路径点支持名称、分组、维度、坐标、六位 RGB 颜色和显示状态。列表可搜索名称、分组和维度，按分组筛选，并将当前筛选结果中的私人点批量分组或切换显示。死亡点按维度分别保留，默认最近 5 个。主世界/下界投影按 1:8 换算 X/Z，投影标记带 `↔`，并不代表存在已建成的传送门。

私人点与公共点可设置世界内导航。选中目标在屏幕外时显示边缘方向提示；未指定目标时最多显示附近 8 个路径点的标签。导航不会自动行走或自动传送。地图传送需要服务器开启配置并授予权限。

## YZUI / YZHUD 适配

- 地图工具页使用现有 YZUI 卡片、按钮、输入框、文字与明暗主题色；主题和视觉风格变更即时生效。
- 小地图支持圆形、方形、圆角方形。地图纹理、线段、标记和文本分别依据同一轮廓裁切，边框采用当前主题强调色。
- 小地图作为独立 `MINIMAP` 组件加入 YZHUD 布局编辑器，与其他 HUD 组件共用透明度设置。
- 默认放在右上角，可自动避让 YZUI 记分板；玩家拖动后优先尊重手动位置。尺寸会适配当前 GUI 可用空间，布局预览使用相同尺寸。
- `F1`、死亡状态、登录大厅与打开其他界面时隐藏小地图；全屏地图仍可通过专门入口使用。

## 地形、雷达与已发现结构

地形只来自已经加载的 `LevelChunk`。采样读取高度、方块地图色、水深、群系颜色、光照等信息；自动模式在玩家深入地表或进入下界时显示洞穴，固定高度按配置切片，顶层模式可查看下界基岩顶板及顶层建筑。洞穴高度按 8 格分段，重载相邻层时渐进补全。

区块网格、生物群系叠加和区块加载状态独立于地形模式。加载状态由服务端可选开放，只报告当前视口中心至多 32×32 个区块：绿色为实体刻范围（票据等级 ≤31），蓝色为方块刻范围（32），黄色为边界范围（33），紫色为更高等级；高缩放下可显示精确等级数字。未开放时不展示这类信息。

本地实体雷达只读取客户端已经收到的实体，支持玩家、敌对、友好及其他实体分类；玩家头像来自正常的 Minecraft 皮肤缓存。连接地图服务后，玩家位置以服务端共享名单为准。服务端过滤未认证、死亡、旁观、原版隐形和本模组隐身玩家，也尊重玩家自己的位置共享开关；实时数据过期后自动撤下。

结构标记读取已加载区块里的实际结构起点。它不读取世界种子、不推算未生成结构，也不调用查找/加载区块来扫描远方。自动结构标记占用公共点池，最多使用公共点上限的一半且不超过 256 个；可关闭 `share_structures`。

## 保存和共享

| 内容 | 位置/边界 |
| --- | --- |
| 客户端显示配置 | `yzwc/client/global_settings.json` → `map_module` |
| 私人路径点、绘图 | 同一文件的 `map_module.worlds[]`，按世界身份区分 |
| 小地图位置、透明度 | 同一文件的 `yzhud_module`，位置键为 `minimap_position_x/y` |
| 服务端开关与限制 | `yzwc/server/config/global_settings.json` → `map_module` |
| 玩家是否共享位置 | `yzwc/server/config/user_settings/<UUID>.json` → `map_module.share_position` |
| 世界身份、公共点、Api 同步时间 | `<world>/data/yzwc/data/map_module/data.json` → `map_module` |
| 已探索地形 | 同目录 `tiles/<维度哈希>/<图层>/<高度>/<区块X>_<区块Z>.gz` |
| PNG 导出 | `<gameDir>/screenshots/yzwc_maps/` |

所有路径均通过 `ModPaths` 取得。服务器为存档保存稳定 UUID，客户端按 UUID 分开保存私人点和绘图；同一服务器地址更换新存档后，不会沿用旧 UUID 的私人数据。未连接地图服务时，单人世界使用存档路径、本机服务器记录使用服务器地址生成身份。

**地形持久化位于专用服务端。** 本模组现有架构只在专用服务端初始化权威服务；单人/原版服务器仍可使用客户端地图、私人点和绘图，客户端地形缓存仅保留到断线。客户端不另建 data/cache 目录，也不上报地形。私人路径点和绘图不上传；公共点、玩家位置及真实已探索地形通过 Minecraft 自定义数据包共享，不启动 HTTP 端口或网页服务。

公共点发布只接收名称、分组、坐标和颜色；所有者、创建时间、共享与锁定状态由服务端决定。普通玩家只能编辑/删除自己的未锁定点；管理员可管理其他人的点并锁定为服务器点。公共操作有结果确认，拒绝或超时时编辑器保留输入。私人点发布为公共点时，确认成功后才移除对应私人记录。

| 配置键 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `true` | 地图共享服务总开关，客户端本机显示独立 |
| `share_terrain` / `share_players` / `share_waypoints` | `true` | 共享地形 / 玩家位置 / 公共点 |
| `share_structures` | `true` | 共享已发现结构标记 |
| `api_upload` / `capture_underground` | `true` / `true` | 每两天上传后台 / 自动采集每 8 格地下切片 |
| `share_load_state` | `false` | 共享区块票据加载等级 |
| `allow_publish` | `true` | 允许普通玩家按权限发布公共点 |
| `allow_teleport` | `false` | 开启后仍需地图传送权限 |
| `max_shared_waypoints` / `max_waypoints_per_player` | `512` / `32` | 公共总量 / 普通玩家配额 |
| `columns_per_tick` / `sampling_budget_micros` | `256` / `2000` | 每 Tick 的全服采样列数和时间预算 |
| `bytes_per_second_per_player` | `131072` | 每位玩家地形同步速率，令牌额度允许发送单个完整瓦片 |
| `cache_tiles` / `capture_radius` | `8192` / `8` | 服务端内存区块数 / 玩家周围采样半径 |

修改服务端配置后执行 `/yzwc reload`。位置共享可以在地图设置中切换，或使用 `/yzwc map position show`、`/yzwc map position hide`。公共点命令为 `/yzwc map shared list`、`add <名称>`（当前位置）、`delete <UUID>`、`lock <UUID>`、`unlock <UUID>`；`/yzwc map stats` 查看该玩家累计收到的地形数量与带宽统计。

| 权限节点 | 无 LuckPerms 时的回退 |
| --- | --- |
| `youzaiworldcore.command.map.shared` | 已认证玩家，另受服务端发布开关限制 |
| `youzaiworldcore.command.map.manage` | OP 4，可管理和锁定公共点、手动上传后台 |
| `youzaiworldcore.command.map.teleport` | OP 4，另需 `allow_teleport=true` |

## YouzaiWorldApi 后台地图

专用服务端通过现有 `ApiHttp` 网桥上传；Api 保存到自己的 SQLite 数据库。后台导航「服务器地图」位于 `/game-maps`，需登录且具备 `game-maps` 页面查看权限。浏览支持存档、维度、地表/顶层/洞穴/固定高度选择，拖动缩放、坐标定位、光照和区块网格；使用后台现有明暗主题。此页为上传快照，非实时游戏画面。

- `map_module.enabled`、`map_module.api_upload` 和 `api_module.enabled` 均开启时自动上传；沿用 `api_module.base_url` 与 `server_key`，密钥与后台游戏 Api 配置一致。已有正常账户网桥无需新增密钥。
- 从未成功同步时，启动约 60 秒后尝试首次上传；以后每次成功后 **48 小时**再上传。同步由真实时钟调度，空服暂停仍可上传已保存地图；同步时间随存档保存，停服期间不运行，逾期在下次开服约 60 秒后补传。失败十分钟后重试，失败不推进增量时间。
- `/yzwc map upload` 可立即安排上传，需 `youzaiworldcore.command.map.manage`（无 LuckPerms 时 OP 4），控制台也可用。命令返回的是已安排状态，完成状态查看后台；排错使用本模组 DebugLogger。
- 平时按已保存瓦片修改时间增量上传；首次、Api 地址变更或后台地图库为空时全量上传。每批至多 128 个瓦片，由 HMAC 保护；只有完整结束才更新成功时间。中断后后台保留已保存数据并显示未完成状态。
- 自动采集监听服务端实际加载的区块，不要求玩家安装客户端模组。每个区块渐进记录地表、顶层和从维度最低到最高处每 8 格的固定高度切片；已保存的洞穴图层也会上传。固定切片从所选高度向下找可绘制方块，并非三维方块存档，也不保证捕获每个狭小洞室。
- 采样与游戏内共享共用 `columns_per_tick` / `sampling_budget_micros`，每轮结束后约五分钟重新采样。卸载会取消未完成采样；短暂加载的区块可能只记录部分图层，再次加载后逐步补齐。安装前已生成但此后从未加载的区域不会自动回填；地图浏览与上传都不强制加载或生成区块。登录大厅不采集。
- 上传仅含地形颜色、高度和光照，不上传私人路径点、绘图或玩家实时位置。数据库按存档 UUID 隔离；每个存档上限 200 万图层区块、后台最多 64 个存档，达到上限会拒绝整批并保留原数据。一个区块多个高度分别计数；数据量随探索范围及图层数增加。
- 浏览请求每页最多 256 个瓦片，视口最多 256×256 区块；前端渐进绘制，仅保留当前视口位图，移动到其他区域可继续查看历史地图。

联动验收：部署本次 Api 代码并更新模组后，加载主世界、下界及负坐标区域，等待切片采样后执行 `/yzwc map upload`，在后台切换维度与地下高度。断网中断上传后重试应保留地图且不重复计数；重启服务端应保留同步时间；空服暂停时仍应按真实时间检查上传。退出后台登录或把页面权限设为隐藏后，地图列表和瓦片接口均应拒绝访问。

## 导入、导出与性能边界

「复制列表」生成本模块版本 1 的路径点 JSON；「复制坐标」生成 `[YZMAP x y z dimension] 名称`，可粘贴导入或放入聊天草稿。分享按钮只打开草稿，玩家自行发送。导入页也接受 Xaero 的 `waypoint:` 数据行和 VoxelMap 的 `name:` 数据行，不包含它们的地形数据库、配置头或其他版本私有字段；这两种外部数据行统一使用导入页指定的维度。

导入先完整解析、预览，再统一校验容量并保存；相同维度、名称与坐标的点会跳过。一次最多读取 256KiB 文本/512 个点，导入后全部是私人点，不继承外部所有权、服务器权限或锁定状态。每个世界最多 512 私人点、128 绘图，每条绘图最多 512 个顶点；客户端最多保存 512 个世界的私人记录。

PNG 默认使用当前视口或选中矩形，可调整边界与每像素方块数，选择是否包含私人绘图与当前维度路径点。未知区域透明，导出只使用点击导出时已有的快照，不会主动加载世界。单边最多 8192 像素，总量最多 16,777,216 像素；导出过程在后台运行，有进度及取消操作。最终文件使用唯一名称，失败/取消时清理本次临时文件。

客户端采样默认每 Tick 256 列，并有约 1.5ms 的预算；地形颜色、光照和像素合成使用同一套逻辑。画布后台合成，最长边不超过 768 像素，每张画布最多一个任务，每 100ms 至多请求一次新画面，主线程只上传完成的纹理。标记和鼠标坐标使用实际显示的视口，避免地形更新较慢时错位。大量移动或新区域会渐进补全，未探索区域保持空白。

磁盘读写独立于服务器 Tick。服务端只对已加载区块采样，按视口分批发送已有数据；缓存、并发读取、待写队列与每个玩家的发送记录都有上限，磁盘积压会暂停新增采样。关服排空写入；写盘失败通过 `DebugLogger` 报告。客户端内存缓存默认 8192 区块，跨多个图层或极大范围浏览时旧缓存会被淘汰；服务器已经保存的地形可以再次按视口取回。

## 验证状态与联机验收

本次完成源码静态检查、注册/语言键一致性检查，并用本地 Minecraft 26.2 原版类核验新用到的接口。 Api 联动另已通过 `pnpm build`、Vue 组件编译及 42 项隔离 SQLite/上传协议检查（不连接线上数据）。遵守项目约定，未由 AI 执行 Gradle 编译、构建、`runServer` 或 `runClient`；下面的渲染与联机行为仍需开发者运行验证。

1. 开发者编译后启动专用服务端，使用两个客户端连接并认证。确认默认 `map_module`、世界数据与客户端 `map_module` 均生成，七类地图 Payload 可用。
2. 步行、飞行、跨区块、进入洞穴/下界，检查地表、固定高度与顶板模式；在负 X/Z 坐标检查区块接缝、鼠标定位和路径点位置。
3. 切换 YZUI 明暗主题、视觉风格和 GUI 缩放，测试三种边框；在 YZHUD 页拖动小地图、调整透明度、重启确认位置保存；按 `F1` 确认隐藏。
4. A 探索后让 B 浏览同一区域；重启服务端再次取回地形和公共点。仅切换地图视口到未知远方，确认不会生成新区域。
5. A 创建/修改/删除公共点，确认 B 收到更新；B 修改 A 的点应被拒绝且输入保留。管理员锁定后 A 无法修改，管理员解锁后恢复。
6. 切换 `share_players`、`share_load_state`、`allow_publish` 并重载。确认关闭位置共享、隐身、旁观和未认证玩家不出现在共享雷达，过期位置自动撤下。
7. 验证无权限与默认关闭时不能地图传送；显式开启并授权后验证目标维度、高度与世界边界校验。
8. 新建私人点、分组、死亡记录和主世界/下界投影；测试重复导入与非法输入。不同服务器/新世界不应混用私人点与绘图。
9. 创建并移动各类绘图，修改文字与颜色，撤销/重做；导出选区 PNG，检查方向、颜色、透明未知区域、标注位置、超大区域拒绝与取消清理。
10. 重绑地图按键，测试按 `M` 关闭不会立即重开，文本输入时不会误触地图快捷键；反复开关地图、切服和修改窗口尺寸，检查无旧世界纹理或过期操作回调残留。通过客户端执行 `/yzwc map shared list`、`/yzwc map position hide` 和 `/yzwc map stats`，确认镜像命令到达服务端并正常返回。
